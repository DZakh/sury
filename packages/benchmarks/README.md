# benchmarks

Generates `docs/benchmarks/*.md`: one page per wire Sury speaks, each with the
same four sections.

```sh
pnpm benchmarks           # remeasure what a machine cannot influence, and fail on a difference
pnpm benchmarks --write   # rewrite the pages, and time the benchmarks into the charts
pnpm benchmarks --charts  # time the benchmarks into .charts/ and touch nothing else
pnpm benchmarks --only=protobuf
```

Three of the four sections are the same on any machine:

- **Bundle size** is esbuild output, minified and gzipped, for the code a
  consumer would actually write.
- **Features** are probes. Each cell is a call run against that library, and the
  page prints what happened. A cell that could not be a probe is marked.
- **Conformance** is a score: a third-party suite where one exists (Google's
  conformance runner, the JSON Schema Test Suite), and a corpus in this package
  where one does not.

The fourth, **performance**, moves with the runner, so it is not committed at
all. `--charts` renders it to `.charts/<topic>-performance.svg` and a dark cut
beside it; a push to main runs that and `scripts/publish-charts.sh`, which puts
the eight files on the `benchmarks` branch. The pages embed them from there by
URL, so a page carries a current timing without anything rewriting its markdown.
Run `--write` or `--charts` to look at a chart before pushing.

`goldens/<topic>.json` is the measured record for the three sections that are
committed; the markdown is rendered from it. Both are regenerated by `--write` -
never edit either by hand.

A new page is `topics/<id>.ts` plus a line in `registry.ts`.
